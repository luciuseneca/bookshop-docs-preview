# Заказы и оплата

**Оформление сразу уменьшает доступный остаток.** Заказ и платёж ждут подтверждения в статусе `pending`. Успешный webhook закрепляет покупку, а отмена неоплаченного заказа возвращает книги на склад.

## Оформление и резерв

- `POST /api/orders` принимает список `book_id` и `quantity` от авторизованного покупателя. Кнопка в корзине отправляет сюда только отмеченные позиции. `POST /api/orders/from-cart` сам читает всю корзину покупателя и передаёт позиции в тот же сценарий. Пустая корзина отклоняется.
- В заказе должно быть **от 1 до 10 позиций**, количество экземпляров в каждой — целое число больше нуля. В PostgreSQL сервер читает строки книг в порядке ID через `SELECT … FOR UPDATE NOWAIT`. Если другой запрос уже держит блокировку книги, оформление сразу возвращает `409`. Под блокировкой сервер проверяет, что каждая книга существует, доступна и её остатка хватает.
- В одной транзакции сервер вычитает экземпляры из `book.quantity`, фиксирует базовую цену книги в каждой позиции (`book.price` до скидки), считает сумму как `Σ(цена × количество)` через `Decimal` и создаёт заказ с одной записью платежа. Если любая позиция не проходит проверку, транзакция откатывает и остатки по предыдущим позициям. После коммита блокировки снимаются, уменьшенный остаток сохраняется.

## Stripe Checkout

После коммита сервер через `asyncio.to_thread` вызывает синхронный SDK Stripe. Сначала создаёт клиента по имени и email, затем платёжную сессию только для карты. Цены передаются в центах USD, срок сессии по умолчанию **30 минут**. В метаданные сессии кладутся `order_id` и `payment_id` для обработки webhook.

Ключ идемпотентности `payment_<payment_id>` относится к созданию Checkout для конкретного платежа. Повторный HTTP-запрос заново запускает оформление. Если остатка хватает, появятся новый заказ, платёж и резерв. После создания Checkout сервер отдельной транзакцией сохраняет ID сессии в `payment.transaction_id` и возвращает `201` с `checkout_url`. Браузер переходит по этой ссылке для оплаты.

Если создание клиента или сессии Stripe выбрасывает исключение, сервер пытается отменить заказ и вернуть остатки отдельной транзакцией. После успешной отмены клиент получает `502`. Сбой процесса между коммитом резерва и сохранением ID сессии оставляет `pending`-заказ для фоновой проверки.

## Webhook и возврат остатков

- `POST /api/orders/webhook` проверяет исходное тело и заголовок `Stripe-Signature` с секретом webhook через SDK. Некорректное тело или подпись дают `400`.
- **`checkout.session.completed`.** По ID из метаданных сервер в одной транзакции меняет статусы платежа и заказа на `success` и `paid`, сохраняет `payment_intent_id` и удаляет купленные книги из корзины по ID. Удаляется вся позиция соответствующей книги, даже если в корзине было больше экземпляров. Остальные позиции сохраняются. Повтор после фиксации `success` заканчивается сразу.
- **`checkout.session.expired`.** Общая операция отмены работает с заказом в `pending`. Она ставит `canceled`, меняет статус платежа на `failed`, если он ещё не `success`, и возвращает экземпляры из позиций заказа под блокировкой строк книг. Повтор после коммита видит `canceled` и пропускает заказ.
- **Резервная отмена.** Планировщик Taskiq каждые 10 минут отправляет задачу через RabbitMQ. Воркер берёт до 100 заказов в `pending`, чей возраст превышает `TTL Checkout + 10 минут` (40 минут по умолчанию), и отменяет каждый в отдельной транзакции. Возраст считает от даты создания заказа в БД. Если строки книг заняты, задача пропускает заказ до следующего запуска.

Проверки статусов выполняются обычным чтением без блокировок строк заказа и платежа. Две параллельные обработки могут прочитать прежний статус, а запоздалый `completed` может перевести отменённый заказ в `paid` после возврата книг. В `completed` также нет отдельной проверки поля Stripe `payment_status`.

`GET /api/orders/success` и `GET /api/orders/cancel` возвращают JSON с текстом и номером из `order_id`. Эти переходы только показывают сообщение.

**Пример.** На складе три экземпляра книги по $9,99. Покупатель оформляет два за $19,98. Остаток сразу становится равен одному. Если Stripe присылает `completed`, остаток остаётся равен одному и купленная книга исчезает из корзины. Если покупатель вернулся по ссылке `cancel`, резерв сохраняется до фактической отмены. После `expired` остаток снова равен трём.
