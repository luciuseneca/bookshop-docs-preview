# Персональные рекомендации

Главная страница запрашивает ленту из четырёх источников через `GET /api/books/main/recommendations` после входа покупателя. **PostgreSQL хранит события, Redis ускоряет чтение профиля и запоминает показы, Qdrant ищет близкие книги и профили.** Пересчёт вектора выполняется в фоне.

## От действия покупателя до профиля

Открытие карточки, поиск по названию или автору внутри категории, добавление в корзину, добавление или удаление из избранного и оценка в отзыве отправляют событие в RabbitMQ. Поиск фиксируется только на первой странице результатов. Сбой публикации логируется, основной запрос завершается независимо. Обработчик очереди валидирует сообщение, добавляет ID автора и категории книги и записывает событие с весом в PostgreSQL. Ошибка обработки отправляет сообщение в очередь проблемных сообщений (DLQ) без автоматической повторной доставки. Повторный просмотр той же книги тем же покупателем в течение **60 секунд** отсекает ключ Redis с `SET NX` и TTL.

| Сигнал | Вес |
| --- | ---: |
| Просмотр / поиск | 0,5 / 0,3 |
| Добавление в избранное / удаление | 1,5 / −0,5 |
| Добавление в корзину / удаление | 2 / −0,3 |
| Покупка / поделиться / предпросмотр | 3 / 1,2 / 0,8 |
| Оценка | `(оценка − 3) × 0,75` |

У покупки, удаления из корзины, отправки ссылки и предпросмотра есть типы и веса, но штатные маршруты этих событий сейчас не публикуют. Авторизованный тестовый POST принимает тип, необязательный ID книги и метаданные, подставляет ID из токена и возвращает `202` после публикации.

Из последних **200 событий** профиль собирает топ-5 категорий и авторов по сумме весов с затуханием `exp(−возраст_в_днях / 30)`, до 10 уникальных поисковых фраз, ID просмотренных или иначе затронутых книг и ID покупок из событий `PURCHASE`. Поисковая фраза без ID книги идёт в текст профиля. Оценка 1 даёт −1,5 к интересу, оценка 5 — +1,5.

## Вектор и фоновый пересчёт

Вектор строится из **70% взвешенного среднего эмбеддингов до 50 последних уникальных книг** и **30% эмбеддинга текста профиля**. Текст для Ollama включает имена авторов, категории, поисковые фразы и фрагменты до пяти описаний. Вес книги для среднего — сумма её событий, ограниченная диапазоном 0,1–3. Итоговый вектор нормализуется и сохраняется в Qdrant вместе с топом категорий и авторов. Одних поисковых фраз для первого вектора недостаточно, поскольку нужны векторы книг.

Redis кеширует профиль и вектор отдельными ключами на **час**. При событии обработчик удаляет оба ключа. До пересчёта лента может взять свежие интересы из PostgreSQL и прежний вектор из Qdrant.

Каждое сохранённое событие увеличивает счётчик версии. Первый флаг `pending` ставит задачу Taskiq на **30 секунд** вперёд. Следующие события продлевают TTL флага до 120 секунд, а задача остаётся на прежнем времени. Воркер берёт Redis-блокировку на 10 минут, проверяет флаг и сравнивает версии до и после расчёта. При изменении версии он ставит ещё один пересчёт. Блокировка удаляется в `finally`. Проверка версии и снятие флага идут отдельными командами, поэтому событие между ними может остаться до следующего запуска.

## Как собирается страница

Цель — **20 книг**. Четыре источника работают параллельно, порядок их слотов перемешивается по seed сессии и номеру страницы.

| Слоты | Откуда берутся книги |
| --- | --- |
| **8 персональных** | Qdrant ищет книги по косинусной близости к вектору пользователя. Попадание в его топ-3 категорий даёт +15% к множителю веса, попадание в топ-3 авторов — ещё +10%. Из кандидатов с весами выбираются книги с мягким пределом по две на автора и категорию. |
| **6 популярных** | Взвешенная выборка по сумме дневных баллов за семь дней от последней даты статистики. При отсутствии статистики на старте используется общий пул с повышенным весом продаж. |
| **4 новинки** | Книги с большими ID. Если у покупателя есть топ категорий, поиск ограничен ими. Чем свежее позиция, тем выше вес. Предел в две книги на категорию снимается, если иначе слот не заполнить. |
| **2 находки** | Проход по индексируемому `random_key` от случайной точки. В конце диапазона поиск продолжается с начала. |

**Если вектора ещё нет**, персональные слоты берут книги из известных категорий по рейтингу и продажам. Если нет и категорий, используется общий пул из топ-200 по продажам и 100 новинок. Пул кешируется на 10 минут. Книги выбираются с учётом продаж, новизны и рейтинга, сглаженного к среднему по пулу. Сглаживание уменьшает влияние одиночной пятёрки.

**Коллаборативный режим** включается, когда векторных кандидатов меньше восьми или счётчик векторной выдачи дошёл до 200. Qdrant находит до 50 похожих профилей. Для каждой категории складываются вклады похожих пользователей `сходство профиля / позиция категории`. Затем Qdrant ищет книги по исходному вектору пользователя внутри выбранной группы категорий. Из персонального источника исключаются книги, отмеченные в профиле как купленные. Доступность в этой ветке зависит от синхронизации индекса Qdrant с каталогом.

При сбое отдельного источника его список считается пустым, а его позиция в курсоре сохраняется. Пустой слот берёт следующего уникального кандидата из доступных списков в порядке «персональные → популярные → новинки → находки». Смешивание использует уже полученные списки, поэтому при сбое или большом числе дублей страница может быть короче. Загрузка самого профиля происходит до запуска источников и при ошибке может прервать запрос целиком.

## Листание и повторные показы

Запрос без курсора создаёт сессию. Лимит — **15 новых сессий за 60 секунд на пользователя**, дальше `429`. Для листания клиент передаёт `next_cursor` в параметре `encoded_cursor`. В курсоре HMAC защищает идентификатор сессии, seed, номер страницы и позиции источников. Битый курсор даёт `400`. Если Redis уже удалил список показов по TTL, подписанный курсор всё ещё принимается, но исключения по старым показам этой сессии теряются. Позиция для популярных — пара «балл, ID», для новинок — ID, для находок — `random_key`. У персонального источника счётчики переключают режим и группы категорий, а уже показанные книги исключаются по ID.

На странице дубли убираются при смешивании. Между страницами Redis хранит последние **400 ID** сессии с TTL **30 минут**. При одновременных запросах к одному курсору оба могут прочитать старый список и выбрать одинаковые книги. Между сессиями отдельно хранятся последние **300 записей о показах** с TTL **3 дня**. Повторный показ остаётся возможен, но вес такой книги для персонального источника и новинок умножается на **0,25**.

**Пример.** Покупатель дважды открыл один детектив за минуту и добавил его в корзину. Профиль получит один просмотр (+0,5) и добавление (+2). До пересчёта детективы уже могут попасть в выдачу по категории. После пересчёта Qdrant ищет семантически близкие книги. Если одна из них уже была на первой странице, её исключат при листании, а в новой сессии она сможет вернуться с пониженным весом.

## Откуда берётся популярность

Taskiq каждый день в **00:10 UTC** пересчитывает предыдущие сутки по UTC. Для доступных книг с активностью за день балл равен **0,60 × число позиций заказа + 0,30 × число записей избранного + 0,05 × число отзывов + 0,05 × текущий рейтинг + 0,10 × число уникальных зрителей**. Учитываются строки позиций за сутки без проверки статуса заказа и без умножения на количество экземпляров. Просмотры считаются по уникальным ID пользователей на книгу за день. Задача обновляет записи PostgreSQL по паре «книга, дата», поэтому повторный запуск пересчитывает те же сутки. Ручной POST ставит ту же задачу в очередь и сразу отвечает `202`. У этого маршрута отсутствует проверка авторизации.
