# Панель менеджера поддержки

Панель показывает очередь, чаты текущего менеджера и архив. **Назначение хранится в PostgreSQL, активное WebSocket-подключение защищает отдельный ключ Redis.** Менеджер может отключиться и позже продолжить тот же разговор.

## Вход и списки чатов

На странице `/support/manager` менеджер входит по email и паролю без одноразового кода. Сервер проверяет пароль и активность аккаунта, выдаёт access JWT с ролью `authorized_manager` и ставит refresh-cookie. Панель хранит access-токен отдельно от витрины. Защищённые HTTP-маршруты сверяют роль из токена с актуальной ролью и активностью в БД.

Вкладки используют один запрос с параметром `status`. Во всех списках сначала идут чаты с наиболее свежим сообщением.

- **Очередь (`queue`).** Все открытые чаты без `manager_id`, в том числе ещё без эскалации.
- **Активные (`active`).** Открытые чаты, назначенные вошедшему менеджеру.
- **Закрытые (`closed`).** Все закрытые чаты. Историю можно прочитать у своего или неназначенного чата, а у назначенного другому менеджеру сервер возвращает `403` даже после закрытия.

## Назначение и переподключение

Панель сначала загружает историю, затем для открытого чата подключает WebSocket с JWT. Уже при подключении к свободному чату сервер проверяет роль менеджера, записывает его ID в `manager_id`, сбрасывает кеш чата покупателя и через Redis Pub/Sub сообщает покупателю, кто взял обращение. Назначенный менеджер может переподключиться без повторного уведомления. Другому менеджеру сервер откажет.

На каждый чат WebSocket создаёт ключ Redis с UUID соединения через `SET NX EX`. Пока ключ существует, второе менеджерское подключение к этому чату отклоняется, в том числе из другой вкладки того же менеджера. При отключении обработчик сверяет UUID и удаляет свой ключ. Срок ключа — **1 час** без продления, поэтому он может истечь при ещё открытом сокете.

Кнопка «Взять в работу» отдельно вызывает HTTP `POST …/assign`. Этот маршрут тоже проверяет `manager_id` и возвращает `409`, если чат уже закреплён за другим. Он обновляет назначение без Redis-блокировки и без блокировки строки при проверке, поэтому параллельное назначение через HTTP и WebSocket может привести к перезаписи.

## Переписка, выход и закрытие

- **История.** API выдаёт сообщения от старых к новым по `limit` и `offset`. Панель загружает по 50, «Показать ещё» сдвигает смещение на число полученных сообщений. Закрытый чат открывается для чтения без нового WebSocket.
- **Ответ.** Панель отправляет текст по WebSocket. Сервер сохраняет сообщение с автором `manager`, обновляет время последнего сообщения и после коммита публикует его в Redis Pub/Sub. Покупатель получает его через свой WebSocket.
- **Возврат в очередь.** Назначенный менеджер может отправить по WebSocket `{"action":"leave"}`. Сервер очищает `manager_id`, сбрасывает кеш, уведомляет покупателя и закрывает соединение. В панели отдельной кнопки для этой команды нет. Переключение на другой чат закрывает сокет и сохраняет назначение.
- **Закрытие.** Кнопка вызывает HTTP `POST …/close` для своего открытого чата. Сервер ставит `is_closed` и `closed_at`, сбрасывает кеши и публикует уведомление. Протокол WebSocket также поддерживает команду `close`.

## Шаблоны ответов

Шаблоны общие для всех менеджеров. У каждого уникальное название до 120 символов и текст до 2000. API поддерживает просмотр по алфавиту, создание, частичное изменение через `PATCH` и удаление. Повтор названия при создании или изменении даёт `409`. В панели можно просмотреть, создать и удалить шаблон. Нажатие на шаблон подставляет его текст в поле ответа, после чего менеджер может изменить черновик и отправить. Изменение самого шаблона доступно через API.

**Пример.** Анна открывает обращение из очереди и автоматически получает его в работу. После закрытия вкладки чат остаётся в её «Активных». Анна снова открывает его, вставляет шаблон «Уточните номер заказа» и дописывает вопрос. Если Анна отправит команду `leave`, этот же чат с прежней историей вернётся в очередь.
